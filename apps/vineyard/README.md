# Виноградник

Навчальна піксельна симуляція догляду за виноградником. Гра починається в жовтні —
одразу після збору врожаю, бо саме осінні роботи закладають урожай наступного року.

```bash
pnpm dev --filter @edu/vineyard
```

## Як це працює

**Хід = місяць.** Щомісяця гравець має обмежену кількість трудоднів (2–6 залежно
від сезону) і обирає, що встигнути. Кожна картка дії пояснює три речі ще до кліку:
навіщо це роблять, чому саме в цей строк і що буде, якщо пропустити.

**Порядок фаз усередині місяця** сам по собі є частиною моделі:

1. **дії гравця** — укриття мусить встигнути захистити лозу від морозу цього ж місяця;
2. **природа** — хвороби наростають, волога випаровується, кущ живе своїм життям;
3. **погода** — перевіряє, наскільки кущ виявився до неї готовим.

**Наслідки відкладені.** Помилка листопада проявляється в березні, а перевантаження
цього року б'є по врожаю наступного. Стан куща (запас поживних речовин, інфекційний
фон, структура ґрунту) переноситься між сезонами.

## Чотири рівні пояснення

| Де | Що показує |
| --- | --- |
| Картка дії | Навіщо / Строк / Ризик — до того, як гравець вирішив |
| Розбір місяця | Що зробили і що це дало (з числами), що зробила погода, що пропустили |
| Річний звіт | З яких множників склався врожай, топ рішень, що переходить у наступний рік |
| Довідник | 25 статей про агроприйоми, хвороби, живлення й фізіологію, з перехресними посиланнями |

## Модель урожаю

```
врожай = 10 кг × живі вічка × навантаження × розмір ягоди × зав'язування × санітарний стан
```

Кожен множник лежить у межах 0…1, тому найнижчий із них обмежує все інше — саме це
й показує річний звіт, сортуючи множники за зростанням.

Ключові залежності, які модель робить відчутними:

- **Навантаження** має оптимум посередині (≈55). Перевантаження карається сильніше
  за недовантаження, бо псує ще й наступний рік.
- **Морозостійкість** набувається заново щоосені й береться з визрівання лози.
  Невизріла лоза не загартовується взагалі, і жодне укриття цього не компенсує.
- **Азот** корисний у квітні-травні й шкідливий у липні-серпні: він зупиняє
  визрівання деревини саме тоді, коли воно має йти.
- **Розмір ягоди** визначається поливом у липні й пізніше не виправляється.

## Регіони

Регіон обирається на старті й змінює календар, ризики та перелік дій:

- **Центр і північ** — укривна культура, зими до −25 °C. Без укриття кущ втрачає
  більшість вічок; це найдорожча помилка гри.
- **Південь** — неукривна, зими до −16 °C. Укриття недоступне й не потрібне,
  натомість головні вороги — посуха й спека.
- **Захід і Закарпаття** — частково укривна, багато опадів. Тут вирішує захист
  від мілдью та сірої гнилі.

## Структура коду

```
src/
├── data/       регіони, календар фенофаз, реєстр дій, довідник
├── game/       модель стану, фази ходу, погода, природні процеси, врожай, перехід у новий рік
├── render/     процедурна сцена й кущ на canvas (без зовнішніх спрайтів)
└── ui/         панель місяця, розбір, річний звіт, довідник
```

## Як додати дію

Додайте запис у [src/data/actions.data.js](src/data/actions.data.js):

```js
{
  id: "unique_id",
  label: "Назва дії",
  category: "soil" | "prune" | "protect" | "green" | "winter" | "harvest",
  laborCost: 1,
  months: [7, 8],              // коли дія з'являється в списку
  bestMonths: [7],             // коли вона доречна
  regions: ["center"],         // не вказувати — доступна всюди
  requires: (state) => state.flags.covered ? null : "Кущ не вкритий",
  why: "…", timing: "…", risk: "…",
  codexRef: "potassium",       // ключ статті в encyclopedia.js
  important: (ctx) => ctx.month === 7,   // пропуск потрапить у «що ви пропустили»
  missed: "Що станеться, якщо не зробити",
  apply: ({ state, month, region, rng }) => [
    e("soil.potassium", 20, "Пояснення саме цієї зміни"),
  ],
}
```

`apply` може повертати різні ефекти залежно від місяця — так зроблено для
азотного підживлення, укриття лози й поливу, де та сама дія в інший строк
дає протилежний результат.

Нові показники додавайте у `LIMITS` в [src/game/model.js](src/game/model.js)
і в `STAT_NAMES` в [src/ui/debrief.js](src/ui/debrief.js), інакше в розборі
з'явиться технічний шлях замість людської назви.

## Джерела агротехніки

Календар робіт і механізми впливу спираються на класичну агротехніку винограду
для умов України: строки укривання після загартувальних морозів, роль калію у
визріванні лози, полярність і суха підв'язка, обломка як нормування навантаження,
критична обробка по зав'язі «з горошину», чеканка в серпні та припинення поливу
перед збором. Числа в моделі — ігрові й відкалібровані так, щоб правильна
агротехніка давала ~7.5–8 кг з куща, а грубі помилки — менше кілограма.
