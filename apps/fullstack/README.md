# По той бік API

Піксельна RPG для фронтенд-розробника, який іде в бекенд. Від React-розробника
до Staff Engineer — через рантайм Node.js, мережу й HTTP, справжній Postgres у
браузері, а далі архітектуру, кеш, черги, безпеку й експлуатацію.

Гра вчить не текстами, а задачами, де помилка має наслідок: код перевіряють
приховані тести, SQL виконує справжній Postgres, порядок виводу event loop
звірено зі справжнім Node, а бос — це продакшн-інцидент із бюджетом помилок.

```bash
pnpm dev --filter @edu/fullstack           # http://localhost:5185
pnpm --filter @edu/fullstack test          # контент, пісочниця, SQL на PGlite, MVCC, бос, прогрес
pnpm --filter @edu/fullstack simulate      # баланс босів
```

## Що в грі

| Режим | Суть |
| --- | --- |
| Мапа | Акти-острови від прологу до Staff; акти «скоро» видно з темами, які там будуть |
| Рівні | 8 типів міні-ігор (нижче); ★ пройдено · ★★ без підказок · ★★★ бонус-ціль |
| Боси | Продакшн-інцидент у 4 фази різних типів; ресурс — бюджет помилок, інструменти одноразові |
| Постмортем | Blameless-розбір після кожного бою: таймлайн із ваших гіпотез, root cause, action items, погляд Staff |
| Герой | Грейд (Frontend → Junior → Middle → Senior → Staff), рівень і XP, дерево навичок, інструменти, титули |
| Стендап | Щоденні картки інтервального повторення (Leitner, `@edu/study-kit`) |
| Довідник | Статті з кодом, цифрами, питаннями зі співбесід і «містком із фронтенду» |

| Тип рівня | Що робить гравець | Чим перевіряється |
| --- | --- | --- |
| `predict` | розставляє вивід `console.log` | еталон звірено з 6 запусками справжнього Node |
| `order` | упорядковує кроки, уникаючи зайвих | порівняння з еталоном |
| `review` | клацає рядки з багами й вразливостями | розмітка рядків із поясненнями |
| `incident` | метрики, логи, трейси → гіпотеза → дія | дерево кроків; хибний варіант показує наслідки |
| `decision` | архітектурний trade-off | ефекти `sim-core` із обов'язковим `reason` |
| `codeQuest` | пише функцію в CodeMirror | приховані тести у Web Worker |
| `sqlQuest` | пише SQL/DDL | справжній Postgres (PGlite): результат, план EXPLAIN, стан, SQLSTATE |
| `isolationLab` | крокує двома транзакціями | детермінований MVCC-симулятор із семантикою Postgres |

Грейд відкривається лише перемогою над босом-«підвищенням». XP, грейд, навички
й інструменти не зберігаються — вони обчислюються з прогресу, тож не можуть
розійтися з тим, що гравець справді пройшов.

## Як це влаштовано

```
src/
  data/      контент: acts/<акт>/{levels,boss,codex,cards,skills,code,sql,labs}.js + реєстри
  game/      чиста логіка: відкриття, зірки, XP, кар'єра, навички, інструменти, бос як машина станів
  progress/  сховище (edu-sim:fullstack) і repairProgress — версію не підвищуємо ніколи
  sandbox/   harness (компіляція коду гравця + тести), шими node:events/stream/http, Redis, фейковий годинник, воркер
  sql/       PGlite у воркері, спільний адаптер для браузера й тестів, чекери задач
  labs/      MVCC-симулятор рівнів ізоляції
  render/    процедурний піксель-арт: мапа, боси, портрет героя
  ui/        екрани та міні-ігри (kinds/*) — один контракт для рівня й фази боса
test/        node --test: контент, коди, predict на справжньому Node, SQL на PGlite, MVCC, бос, шими
scripts/     simulate.mjs — баланс босів
```

Принципи, на яких тримається правдивість гри:

- **Шими звірено з Node.** `test/shims.test.js` проганяє однакові сценарії на наших
  `EventEmitter`/`Writable` і на `node:events`/`node:stream`; траси мусять збігтися.
- **Predict — лише детерміновані сніпети.** Кожен запускається справжнім Node 6 разів,
  половина — з busy-wait, що ловить гонку `setTimeout(0)` проти `setImmediate`.
- **SQL-перевірки — на тому самому Postgres.** Датасети арифметичні, ≤ 30 000 рядків і з
  `ANALYZE`, тож плани детерміновані; очікуване обчислюється еталоном на свіжому датасеті.
- **Кожна задача коду має `naive`.** Правдоподібний хибний розв'язок мусить падати —
  інакше тести не ловлять головну пастку задачі.

## Чесні обмеження

- Пісочниця — браузерний воркер, а не Node: `fs`, `net`, `Buffer` і `node:crypto`
  недоступні. Специфіку Node тренують шими (звірені з Node), predict-рівні й review.
- PGlite — однокористувацький Postgres, тому конкурентні транзакції показує MVCC-симулятор.
  Він навмисно вузький: дві транзакції, маленька таблиця, семантика RC / RR / SERIALIZABLE,
  `FOR UPDATE` і дедлоки.
- NestJS-рантайму в браузері немає; акт про NestJS (скоро) працюватиме через review,
  order і задачі на DI-контейнер у пісочниці.
- Postgres (~3,5 МБ у gzip) вантажиться лише на SQL-рівнях і в SQL-фазі боса.
